# Wireshark reference for FlowTwin's packet inspector

Research date: 2026-10-27. Scope: functional and architectural reference only, from the official [wireshark/wireshark repository](https://github.com/wireshark/wireshark), a read-only mirror of Wireshark's upstream GitLab repository. The GitHub connector fetched the repository metadata and the files cited below. All source links are pinned to the observed master commit [`e80410714e8292569a41db153abbbdc0d7d5edc7`](https://github.com/wireshark/wireshark/commit/e80410714e8292569a41db153abbbdc0d7d5edc7).

No GPL code, assets, Qt components, or dissector implementations were copied or reused. The adaptation recommendations below are independent design proposals, not claims that Scapy provides Wireshark feature parity.

| Compile versus apply filters | `dfilter_compile_full` compiles text with structured error information; `dfilter_apply_edt` and `dfilter_apply` apply the compiled filter to a dissection or protocol tree. [filter API, lines 140–219](https://github.com/wireshark/wireshark/blob/e80410714e8292569a41db153abbbdc0d7d5edc7/epan/dfilter/dfilter.h#L140-L219) | Implement a deliberately documented subset of display filters with a server-side lexer/parser and typed fields. ## Minimal implementation contract

These are proposed boundaries, independent of Wireshark's C/Qt interfaces:

- Packet list endpoint: capture-scoped stable packet ID; timestamp; source/destination; protocol; captured/wire lengths; summary; pagination and the applied filter. SQLite indexes should serve existing capture/packet lookup patterns.
- Packet detail endpoint: metadata, original bytes encoded for JSON, hierarchical fields, and optional `{source_id, offset, length}` per field. Keep display labels separate from typed values and filter names.
- Filter validation: return a useful parse/type error with a position; applying an invalid filter returns a client error, not an unfiltered result. Document the actual supported operators, fields, precedence, and literals instead of claiming the full Wireshark language.
- Stream endpoint: endpoints, direction labels, ordered chunks with packet provenance, missing ranges, and truncation status. Restrict the initial feature to TCP; UDP datagrams are a different representation.
- Trust boundaries: validate upload/capture identifiers, sizes and pagination; bound stream output and decoding work; sanitize/download-safe filenames. Keep raw bytes out of routine logs.

Useful acceptance fixtures: known field offsets with IP/TCP options; truncated headers; valid and invalid compound filters; TCP out-of-order segments, retransmissions/overlap, missing segments, both directions, sequence wrap, and a second connection reusing endpoints. These checks test behavior rather than reproducing Wireshark implementation details.

## License boundary

Wireshark's [README licensing section](https://github.com/wireshark/wireshark/blob/e80410714e8292569a41db153abbbdc0d7d5edc7/README.md#L218-L245) states distribution under GNU GPLv2, notes that most files are GPL version 2 or later, and explicitly says its libraries remain GPL rather than LGPL. The inspected Qt and EPAN files carry `GPL-2.0-or-later` headers. The [COPYING license](https://github.com/wireshark/wireshark/blob/e80410714e8292569a41db153abbbdc0d7d5edc7/COPYING) is the full license text.

FlowTwin should implement the user-facing behavior independently using its existing React, FastAPI, Scapy, and SQLite stack. This research introduces no Wireshark library linkage or code reuse. Existing dependency licenses, including Scapy's, remain a separate distribution consideration; they were not audited here.

Research limits: source inspection only; no Wireshark build or interactive runtime test, no full protocol audit, and no benchmark. This note does not promise Wireshark-compatible filtering, dissection coverage, or reconstruction accuracy.
